# SentryFlow AI 最终产品设计

## 项目名称

**SentryFlow AI**

副标题：

**把 eufy 摄像头的一夜告警，变成早上 30 秒能读完的安全交接。**

## 产品一句话

```text
eufy 摄像头的晨间安防交接。
```

## 一句话介绍

SentryFlow AI 是面向 eufy 智能安防场景的 AI 安防交接服务。它把夜间摄像头告警整理成晨间摘要、事件解释、误报说明、风险原因、建议动作和处置状态，让用户早上只处理真正重要的一件事。

## 项目定位

SentryFlow AI 不做重型 CCTV 平台，也不做泛化的视频分析后台。

它验证的是一个更贴近 eufy 的产品机会：

```text
让 eufy 摄像头从“会报警的设备”，变成“会交接的值守助手”。
```

传统摄像头已经能完成“看见”和“提醒”，但没有解决“告警之后怎么办”：

- 告警太多，用户逐渐不看。
- 误报太多，真正风险被淹没。
- 用户不想每天翻几十段视频。
- 早上开门、交班或出门前，只想知道今天先处理哪一件事。

SentryFlow AI 的核心价值不是多识别几个类别，而是完成一次清楚交接：

```text
昨晚发生了什么？
哪些不用管？
哪一件必须处理？
为什么有风险？
现在该通知谁、检查哪里、关闭什么状态？
```

## 核心场景

主场景固定为：

```text
闭店后一夜 47 条告警，早上只处理 1 件事。
```

示例：

- 店铺闭店后，eufy 摄像头产生 47 条 motion alerts。
- 系统复核后发现：44 条是雨水、车灯、昆虫或普通低风险运动。
- 2 条是已解释事件，例如员工返回取货。
- 1 条需要处理：后门 02:13 有陌生人停留 38 秒。
- 用户早上打开交接页，只看到这一条待处理动作：检查后门门锁，并通知店长复核画面。

核心记忆点：

```text
47 条告警 -> 1 个清楚动作
```

## 核心用户

### 1. 小商铺老板

典型状态：

- 店里已有 eufy 摄像头。
- 每天收到大量 motion alerts。
- 半夜不想被频繁打扰。
- 早上又担心漏掉真正风险。

他关心：

- 昨晚店铺是否安全。
- 后门、收银台、仓库门口有没有异常。
- 今天开门前要不要检查门锁。
- 是否需要通知店长或值班人员复核。

SentryFlow AI 给他的结果：

```text
47 条告警里，只有 1 件需要你开门前处理。
```

### 2. 仓库管理员

典型状态：

- 夜间无人值守。
- 后门、围栏、装卸区是重点区域。
- 告警如果没有优先级，很容易被忽略。

他关心：

- 是否有人在敏感区域停留。
- 是否有员工异常返回。
- 哪个摄像头、哪个区域今天要优先检查。
- 是否需要安排巡检或通知现场负责人。

SentryFlow AI 给他的结果：

```text
昨晚哪些事件已解释，哪一件需要复核，今天先检查哪里。
```

### 3. eufy App 用户

典型状态：

- 已经习惯用 eufy App 查看家庭或小型场所安全事件。
- 会收到运动检测、人形检测、门口活动等提醒。
- 不想每天翻历史告警。

他关心：

- 昨晚有没有值得注意的安全事件。
- 哪些是误报或普通经过。
- 是否需要检查门口、后院、车库或门锁。
- 能不能用一句话知道昨晚是否安全。

SentryFlow AI 给他的结果：

```text
eufy App 每天早上自动给出一份 Daily Security Handoff。
```

## 用户完整路径

### Step 1：收到夜间告警

eufy 摄像头在闭店后产生运动事件。事件可能来自雨水、车灯、昆虫、员工活动、普通路过，也可能是真正风险。

系统把这些事件统一成 Event Schema，记录：

- 事件时间。
- 摄像头位置。
- 触发类型。
- 截图或短视频。
- 设备状态。
- 场景上下文。

### Step 2：早上打开交接页

用户早上打开 eufy App 或网页交接页，第一眼看到：

```text
47 条告警已复核
44 条已忽略
2 条已解释
1 条需要处理
```

页面不要求用户先看全部视频，而是直接把待处理事件放到最上面。

### Step 3：查看高风险事件证据

用户点开 `后门 02:13` 事件，看到：

- 摄像头：BackGate-01。
- 时间：02:13。
- 区域：后门。
- 事件：陌生人停留 38 秒。
- 风险等级：High。
- 证据点：营业外时间、敏感区域、人员停留时间较长。

### Step 4：阅读 AI 解释

系统解释这条事件为什么值得进入交接：

```text
该事件发生在闭店后，位置是后门区域，画面中有人停留 38 秒，
不是普通经过，也不像雨水、车灯或昆虫造成的误报。
```

### Step 5：询问 AI

用户可以直接问：

```text
昨晚有什么异常？
今天先处理哪里？
哪些是误报？
```

AI 只基于当前 reviewed events 和 handoff summary 回答，不编造不存在的事件。

### Step 6：通知店长

用户点击：

```text
通知店长复核
```

系统生成可发送内容：

```text
昨晚 02:13 后门出现陌生人停留 38 秒。
请开门前检查后门门锁，并复核 BackGate-01 画面。
```

处置状态从：

```text
Action needed -> Assigned
```

### Step 7：关闭交接

店长复核后，用户点击：

```text
标记已复核
```

状态变成：

```text
Assigned -> Handoff closed
```

当天交接完成，系统保留事件记录和处置结果。

## 产品输出

### 1. 晨间摘要

给用户一个快速结论：

```text
昨晚整体安全。47 条告警已复核，44 条忽略，2 条已解释，1 条需要处理。
优先处理：02:13 后门陌生人停留。
```

### 2. 事件解释

对关键事件说明发生了什么：

```text
02:13，BackGate-01 捕捉到一名陌生人在后门区域停留约 38 秒。
```

### 3. 误报说明

对不需要处理的事件说明为什么忽略：

```text
雨水、车灯反光、昆虫靠近镜头、普通路过，没有进入待处理清单。
```

### 4. 风险原因

说明为什么这件事值得关注：

```text
事件发生在营业外时间，位置是后门敏感区域，人员停留时间超过普通经过。
```

### 5. 建议动作

把判断转成具体动作：

```text
开门前检查后门门锁，并通知店长复核 02:13 的后门画面。
```

### 6. 处置状态

每条待处理事件都有状态：

```text
Action needed
Assigned
Reviewed
Handoff closed
```

## 功能模块

### 1. 事件接入

当前 Demo：

- 使用模拟 eufy 事件流。
- 使用本地 JSON 数据。
- 固定 47 条夜间告警。

未来接入：

- eufy 运动事件。
- 事件截图或短视频。
- 摄像头位置和设备状态。

### 2. AI 事件复核

输入：

- 截图或短视频。
- 摄像头位置。
- 事件时间。
- 设备状态。
- 营业时间和区域规则。

输出：

- 事件摘要。
- 风险等级。
- 误报可能。
- 证据点。
- 风险原因。
- 建议动作。
- 是否需要人工复核。

### 3. 风险排序

排序依据：

- 是否营业外时间。
- 是否敏感区域。
- 是否有人停留。
- 停留时间是否异常。
- 是否可能是天气、反光、昆虫或员工活动。

输出：

```text
Ignored / Explained / Action needed
```

### 4. 晨间交接生成

把夜间事件压缩成用户可读摘要：

- 昨晚是否安全。
- 总共有多少告警。
- 哪些不用管。
- 哪些已解释。
- 哪一件必须处理。
- 今天先做什么。

### 5. AI 问答

支持固定问题：

- 昨晚有什么异常？
- 今天先处理哪里？
- 哪些是误报？

回答边界：

- 只基于当前事件和交接摘要。
- 不编造不存在的摄像头或事件。
- 不做绝对安全承诺。
- 高风险事件必须建议人工复核。

### 6. 处置闭环

支持动作：

- 通知店长复核。
- 安排巡检。
- 标记已复核。
- 关闭交接。

状态流转：

```text
Action needed -> Assigned -> Reviewed -> Handoff closed
```

## 为什么适合 eufy

### 运动事件

eufy 摄像头已经能产生运动、人形、门口活动等事件。SentryFlow AI 不替代这些能力，而是把事件整理成用户能处理的交接结果。

### 夜视和证据素材

夜间安全事件依赖夜视截图或短视频。SentryFlow AI 把这些证据和时间、区域、设备状态结合起来，减少用户自己翻视频的成本。

### 本地存储和 HomeBase

安全场景天然需要隐私控制。SentryFlow AI 未来适合结合 eufy 的本地存储、HomeBase 和隐私策略，只输出必要摘要和授权证据。

### eufy App

晨间交接最自然的入口是 eufy App。用户不需要进入复杂后台，只需要在早上看到一张 Daily Security Handoff 卡片。

### 产品升级方向

SentryFlow AI 可以把 eufy 摄像头从硬件设备升级成轻量安防服务：

```text
会报警 -> 会解释 -> 会交接 -> 会推动处理
```

## 产品边界

### 不做什么

- 不做重型 CCTV 平台。
- 不做完整 NVR。
- 不做大型安防指挥中心。
- 不做生产级多摄像头调度。
- 不承诺官方 eufy SDK 已经接入。
- 不替代安保责任人。
- 不自动做最终安全裁决。
- 不把远程能源、轻工业或太阳能场站作为当前主线。

### 当前 Demo 做什么

- 使用模拟 eufy 事件流。
- 展示 47 条告警到 1 个动作的完整闭环。
- 展示事件复核、风险排序、晨间摘要、AI 问答和处置状态。
- 展示 SDK 可用和 SDK 不可用时的双路径设计。

### 风险事件处理原则

- 高风险事件必须给出证据点。
- 不确定事件必须提示人工复核。
- AI 只能辅助解释和交接，不能替用户承担安全责任。
- 任何“可能入侵”都不表达为“确定入侵”。
