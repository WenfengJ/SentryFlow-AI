# 20 Demo Video Storyboard

这份脚本用于录制 SentryFlow AI Demo Video。录屏时使用 `prototype/handoff-agent.html`，按时间段完成点击和讲解。

## 1. 录制准备

打开原型：

```text
prototype/handoff-agent.html
```

推荐录制画面：

- 浏览器缩放：90% 或 100%。
- 录制区域：浏览器内容区，不录桌面隐私信息。
- 初始状态：页面停留在顶部总览。
- 鼠标动作：慢一点，点完后停 1-2 秒。

录制前确认：

- 页面显示 `SentryFlow AI`。
- 页面显示 `eufy Morning Handoff`。
- 页面显示 `47 / 44 / 2 / 1`。
- 右侧有三个问答按钮。
- 处置按钮可点击。

## 2. 90 秒版

### 0-15 秒：痛点

画面：打开总览页顶部。

操作：不点击，停留在产品名和总览区。

旁白：

```text
摄像头已经很会提醒，但用户真正头疼的是提醒之后怎么办。一个小商铺老板早上打开手机，可能看到一夜 47 条 motion alerts，其中大多数只是雨水、车灯、昆虫或普通路过。
```

画面重点：

- `SentryFlow AI`
- `eufy Morning Handoff`
- `47 条告警已复核。开门前只处理 1 件事。`

### 15-35 秒：47 -> 1 总览

画面：点击 `开始昨晚事件回放`。

操作：

1. 点击 `开始昨晚事件回放`。
2. 鼠标移动到四个指标卡。
3. 停在 `Action needed: 1`。

旁白：

```text
SentryFlow AI 把昨晚 47 条告警先做复核：44 条忽略，2 条已解释，最后只留下 1 条需要今天早上处理的事件。
```

画面重点：

- `47 Total alerts`
- `44 Ignored`
- `2 Explained`
- `1 Action needed`

### 35-60 秒：后门事件详情

画面：事件列表和详情区。

操作：

1. 点击左侧 `Back Gate lingering`。
2. 鼠标停在中间详情区。
3. 指向时间、摄像头、区域和风险原因。

旁白：

```text
需要处理的是后门 02:13 事件。BackGate-01 看到陌生人在后门停留 38 秒。它发生在闭店后，位置是后门敏感区域，也不像雨水、昆虫或车灯误报，所以系统把它标记为 high，并要求人工复核。
```

画面重点：

- `BackGate-01 · 02:13`
- `后门`
- `High`
- 风险原因
- 证据点
- 建议动作

### 60-75 秒：AI 问答

画面：右侧 Ask SentryFlow AI。

操作：

1. 点击 `今天先处理哪里？`
2. 等回答出现。
3. 鼠标停在回答区域。

旁白：

```text
用户也可以直接问：今天先处理哪里？AI 只基于当前交接数据回答，明确指向后门、02:13 的 BackGate-01 画面，并给出下一步动作。
```

画面重点：

- `今天先处理哪里？`
- `先处理后门`
- `复核 02:13 的 BackGate-01 画面`

### 75-90 秒：通知店长并关闭交接

画面：右侧处置区。

操作：

1. 点击 `通知店长复核`。
2. 展示 `Assigned`。
3. 点击 `标记已复核` 两次，展示 `Handoff closed`。

旁白：

```text
最后，用户可以通知店长复核，安排巡检，并关闭今日交接。47 条告警，最后只留下 1 个清楚动作。
```

画面重点：

- `Assigned`
- `Handoff closed`
- `今日不再重复提醒`

## 3. 3 分钟版

### 0:00-0:30 痛点

画面：总览页顶部，停留 5 秒后慢慢移动到四个指标。

旁白：

```text
小商铺和仓库用户并不缺摄像头告警。真正的问题是，告警太多以后，用户不知道早上应该先看哪一条。雨水、反光、昆虫、车灯、普通路过都会触发 motion alerts，真正的风险很容易被淹没。
```

补充讲法：

```text
所以我们没有做一个更复杂的监控后台，而是做一个晨间安防交接。
```

### 0:30-1:00 产品一句话

画面：产品名、总览标题和四个指标。

旁白：

```text
SentryFlow AI 是 eufy 摄像头的 Morning Handoff。它每天早上把一夜告警整理成一份交接：昨晚发生了什么，哪些不用管，哪一件必须处理，为什么有风险，现在该通知谁。
```

操作：

1. 点击 `开始昨晚事件回放`。
2. 等状态显示 replay complete。

补充讲法：

```text
这个 Demo 里，昨晚有 47 条告警。系统复核后，44 条忽略，2 条解释，1 条需要处理。
```

### 1:00-2:10 Demo 操作

#### 1:00-1:25 总览和事件列表

画面：总览 + 左侧事件列表。

操作：

1. 指向 `Action needed / Explained / Ignored`。
2. 点击 `Back Gate lingering`。

旁白：

```text
左侧不是普通历史告警列表，而是 AI 复核后的队列。Action needed 只有 1 条，Explained 有 2 条，Ignored 有 44 条。
```

#### 1:25-1:50 高风险事件详情

画面：中间事件详情。

旁白：

```text
这条事件发生在 02:13，摄像头是 BackGate-01，区域是后门。AI 给出的解释是：陌生人在后门停留 38 秒。风险原因是闭店后、后门敏感区域、停留时间超过普通经过。
```

#### 1:50-2:10 问答和处置

画面：右侧问答区和处置按钮。

操作：

1. 点击 `今天先处理哪里？`
2. 点击 `通知店长复核`。
3. 点击 `安排巡检`。

旁白：

```text
用户不用读长报告，可以直接问今天先处理哪里。AI 指向后门，并给出可执行动作：检查门锁，通知店长复核 02:13 画面。点击后，状态进入 Assigned。
```

### 2:10-2:40 技术架构

画面：滚动到底部 `Demo pipeline`。

旁白：

```text
技术上，我们把真实 SDK 和模拟事件流都放在事件来源层。后面统一进入 Event Schema，再进入 AI Review、Risk Engine、Handoff Summary 和 Q&A Actions。
```

补充讲法：

```text
当前 Demo 不承诺已经接入官方 eufy SDK。我们使用模拟事件流保证现场稳定。如果官方 SDK 或设备可用，可以替换 adapter，后面的流水线不需要重写。
```

画面重点：

```text
eufy / mock events
-> Event Schema
-> AI Review
-> Risk Engine
-> Handoff + Actions
```

### 2:40-3:00 eufy 适配和收尾

画面：回到右侧处置区或保持架构区。

操作：

1. 如果画面在处置区，点击 `标记已复核`，进入 `Handoff closed`。
2. 如果画面在架构区，鼠标停在 `SDK 可替换`。

旁白：

```text
这个方向适合 eufy，因为它不是替代摄像头，而是把 eufy 已有的运动事件、夜视证据、本地存储和 App 触达，升级成每天早上的安防交接。47 条告警，最后只留下 1 个清楚动作。
```

## 5. 录制检查

录制完成后检查：

- 90 秒版不超过 95 秒。
- 3 分钟版不超过 3 分 10 秒。
- 视频里能看到 `47 / 44 / 2 / 1`。
- 视频里能看到 `BackGate-01 · 02:13`。
- 视频里能看到 `今天先处理哪里？`。
- 视频里能看到 `Assigned` 或 `Handoff closed`。
- 视频里明确说出当前 Demo 使用模拟事件流，不承诺已接入官方 SDK。
- 视频结尾回到一句话：`47 条告警，最后只留下 1 个清楚动作。`
