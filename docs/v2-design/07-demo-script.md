# 07 Demo 路演脚本

SentryFlow AI v2 的现场路演脚本，覆盖 3 分钟正式演示、90 秒短版和演示前检查。

主线：

```text
闭店后一夜 47 条告警，老板真正需要处理的只有 1 件事。
SentryFlow AI 把 eufy 摄像头从“会报警的设备”，升级成“会交接的值守助手”。
```

## 1. 3 分钟总结构

| 时间 | 内容 | 目标 |
| --- | --- | --- |
| 0:00-0:30 | 问题开场 | 让评委立刻理解痛点 |
| 0:30-1:00 | 产品一句话 | 说明 SentryFlow AI 是什么 |
| 1:00-2:20 | Demo 演示 | 展示 47 条告警到 1 个行动建议的闭环 |
| 2:20-2:45 | 技术和 eufy 适配 | 说明不是纯 PPT，有可落地架构 |
| 2:45-3:00 | 商业价值收尾 | 强化少看、少跑、少漏 |

## 2. 开场 30 秒

```text
很多小商业不是没有摄像头，而是没人有精力看摄像头。

一个小商铺或仓库闭店后，eufy 摄像头可能一夜产生几十条 motion alerts。
雨水、车灯、昆虫、员工返回取货、陌生人停留，都会混在一起。

老板第二天真正需要知道的，不是“昨晚有 47 条告警”，而是：
哪一件是真的风险？今天开门前先处理什么？
```

演示动作：

- 打开 Demo 首页或总览页。
- 指向顶部数字：`47 alerts reviewed -> 1 action needed`。

## 3. 产品一句话 30 秒

```text
SentryFlow AI 做的不是另一个监控后台。

它是面向小商业、仓库、轻工业和远程边缘资产的 eufy AI 安防交接服务。

我们把 eufy 摄像头的一夜告警，整理成一份早上 30 秒能读完的安全交接：
哪些是误报，哪些已经解释，哪一件需要处理，以及下一步该怎么做。
```

可强调的英文短句：

```text
From 47 alerts to 1 clear action.
```

## 4. Demo 演示 80 秒

### 4.1 第一步：启动昨晚事件回放

```text
现在我们模拟一个小仓库闭店后的夜间事件。
系统接收到 47 条来自 eufy 摄像头的运动告警。
```

演示动作：

- 点击 `开始昨晚事件回放`。
- 页面显示事件复核过程或总览统计。

讲解重点：

```text
这里可以接真实 eufy SDK，也可以用模拟事件流。
为了保证黑客松现场稳定，我们先把事件统一成同一个 Event Schema。
```

### 4.2 第二步：AI 复核和降噪

```text
SentryFlow AI 会逐条复核这些事件。

结果是：
44 条被判断为雨水、车灯、昆虫或普通低风险运动；
2 条被解释为员工活动；
只有 1 条需要处理：后门 02:13 出现陌生人停留 38 秒。
```

演示动作：

- 展示左侧事件列表。
- 指向 `Ignored`、`Explained`、`Action needed` 分类。

讲解重点：

```text
这里的核心不是识别到“有人”，而是判断这个事件是否值得进入交接。
```

### 4.3 第三步：打开待处理事件

```text
我们点开这条后门事件。

系统给出三个信息：
发生了什么，为什么有风险，以及建议怎么处理。

它判断这是营业外时间、后门区域、人员停留时间较长，所以建议开门前检查后门门锁，并请店长复核 02:13 的画面。
```

演示动作：

- 点击高风险事件。
- 展示截图/证据区、风险解释、建议动作。

讲解重点：

```text
用户不需要自己翻几十段视频，只看这一条有证据、有原因、有动作建议的交接结果。
```

### 4.4 第四步：问答和处置闭环

```text
店主还可以直接问：今天先处理哪里？

系统回答：先检查后门门锁，并请店长复核 02:13 的后门画面。

然后店主点击“通知店长复核”或“安排巡检”，交接状态从 Action needed 变成 Assigned。
```

演示动作：

- 在问答框选择或输入：`今天先处理哪里？`
- 展示回答。
- 点击 `通知店长复核`。
- 状态变为 `Assigned` 或 `Handoff closed`。

讲解重点：

```text
这就是完整闭环：不是 AI 分析完就结束，而是把结果送到负责人手里，并推动下一步处理。
```

## 5. 技术和 eufy 适配 25 秒

```text
技术上，我们把系统拆成几层：

第一层是事件适配层，可以接 eufy SDK，也可以接模拟事件流。
第二层是 AI 事件复核，分析截图、时间、位置和设备状态。
第三层是风险排序和误报判断，把几十条告警压缩成可处理的交接结果。
最后是晨间交接摘要、问答和处置状态。

如果现场 SDK 可用，我们接真实设备；如果 SDK 不稳定，模拟事件流也能证明同一套产品闭环。
```

演示动作：

- 快速展示架构图或技术说明页。

## 6. 商业价值收尾 15 秒

```text
AI 视频分析已经存在，真正的机会是产品形态。

企业级 AI CCTV 太重，消费级摄像头太偏家庭。
eufy 的机会，是把普通摄像头套餐升级成“有人值守感”的轻量安防服务。

SentryFlow AI 的价值就是三句话：
少看，少跑，少漏。
```

最后一句：

```text
我们不是多做一个报警功能。
我们让 eufy 摄像头每天早上交代清楚：昨晚发生了什么，风险是否真实，今天先处理什么。
```

## 7. 90 秒短版脚本

用于短视频提交或限时介绍。

```text
很多小商业不是没有摄像头，而是没人有精力看摄像头。
闭店后一夜，eufy 摄像头可能产生 47 条 motion alerts，但老板真正需要知道的，可能只有一件事。

SentryFlow AI 是一个 eufy AI 安防交接服务。
它把一夜的摄像头告警整理成早上 30 秒能读完的安全交接。

在这个 Demo 里，系统复核 47 条告警：
44 条是雨水、车灯、昆虫等低风险事件；
2 条是员工活动；
只有 1 条需要处理：后门 02:13 有陌生人停留。

系统给出证据、风险原因和建议动作：开门前检查后门门锁，并请店长复核这段画面。
店主还可以问“今天先处理哪里”，系统直接给出优先动作。
最后，店主点击通知店长，交接完成。

技术上，我们用统一 Event Schema 支持两条路径：SDK 可用时接真实 eufy 事件，SDK 不可用时用模拟事件流保证现场 Demo 稳定。

我们的价值不是多识别几个类别，而是少看、少跑、少漏。
把 eufy 摄像头从会报警的设备，升级成会交接的值守助手。
```
